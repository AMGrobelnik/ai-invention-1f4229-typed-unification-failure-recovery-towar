## Full Summary

This research establishes a typology of five structurally distinct failure modes in text-to-first-order-logic (FOL) pipelines and maps Prolog's ISO standard exception signals to each type: (1) Lexical Mismatch (predicate name variation, goal failure with no exception), (2) Arity Mismatch (argument count mismatch, type_error or unification failure), (3) Missing Domain Fact (exhausted proof clauses requiring abduction), (4) Ontological Category Violation (external type-constraint violation detected via ontology), and (5) Quantifier Scope Conflict (multiple valid FOL interpretations with contradictory conclusions). The research surveys repair strategies across four neuro-symbolic systems—NLProlog (soft-unification via embeddings), RECOVER (ontology-grounded failure detection with LLM replanning), Probabilistic Abductive CommonSense (PACS, sampling diverse commonsense beliefs), and ARGOS (iterative solver-feedback loop)—and finds that current systems deploy generic repair prompts without failure-type discrimination. The work operationalizes this gap by proposing five type-specific repair prompt templates and a decision-tree framework for diagnosing failure types from Prolog runtime signals. Key empirical findings: (1) NLProlog achieves competitive multi-hop QA via embedding-based soft-unification, but requires training and is unclear on ontological violations [2]; (2) RECOVER achieves 100% failure detection on controlled domains (OntoThor kitchen) via logical rules, but requires manual ontology engineering [3]; (3) PACS outperforms chain-of-thought and prior neurosymbolic methods (LLM-Tres, ARGOS) by explicitly sampling diverse commonsense belief sets and voting [4]; (4) Predicate extraction is the main bottleneck in text-to-FOL translation, with 15–20% performance gains from predicate availability [6]; (5) RuleTaker and CLUTRR benchmarks measure reasoning depth but lack explicit failure-mode annotations, preventing direct evaluation of failure-type detection accuracy. The output provides a decision tree mapping Prolog exception signals to failure types, failure-type-specific detection heuristics with concrete examples, and five repair prompt templates that can be integrated into neuro-symbolic text-to-FOL pipelines to achieve higher precision and reduced hallucination compared to generic fallback strategies.
