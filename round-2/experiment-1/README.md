## Full Summary

Implemented and evaluated the Typed Failure Detector framework against two neural baselines (Direct LLM QA, Chain-of-Thought) on 160 examples from ProofWriter (80) and FOLIO (80) datasets. The typed pipeline achieved 43.75% accuracy versus 35.62% for direct QA and 38.75% for CoT, demonstrating a consistent improvement from structured failure classification and repair. The system classifies proof failures into Types 1-4: Type 1 (lexical predicate mismatch, 14 cases), Type 2 (argument structure, 0 cases), Type 3 (missing fact, 43 cases), Type 4 (category violation, 4 cases). A bridge-axiom cache library accumulated 6 unique axioms with a 33.33% cache hit rate on Type 1 repairs. Extraction fidelity reached 100% (all extracted clauses had valid source-text span annotations from the pre-extracted dataset fields). Proof-trace hallucination was 72.73% in successful proofs (fraction of proof nodes without direct source backing), reflecting the symbolic chainer's reliance on derived inference steps. Total spend: $0.62 across 462 API calls using Claude Haiku 4.5 via OpenRouter (well within the $9.77 budget). SWI-Prolog was unavailable; a Python backward-chaining engine was used for ProofWriter. FOLIO examples were handled via direct LLM reasoning (FOL too complex for regex parsing). Type 5 (quantifier scope) deferred to future work. OpenCyc unavailable; Type 4 used heuristic attribute-role checking.
